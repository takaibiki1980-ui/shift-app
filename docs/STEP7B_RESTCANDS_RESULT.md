**重要な留保**: 本シミュレーションの Before 基準値（0.013〜0.020/trial）は、Step6-B で測定した実際の App.jsx 相当の baseline（17.9〜18.0/trial）と大きく乖離している。

理由: 本検証スクリプトは PassC（連続勤務修正）・比率指定PassB・ロック日複雑性（有休/シフト希望）・外国人夜勤サポーター制約等、App.jsx の autoGenerate に存在する他の制約を含まない簡易再現のため、minStaff保証フェーズ（優先①②）だけで shortage がほぼ解消してしまう。

→ **この検証は「優先②条件緩和の単体効果がプラスに作用するか」を示すには十分だが、「本番 17.9/trial の shortage をどれだけ削減するか」の定量評価としては不十分**。t値（1.42〜1.75）も 1.96 を下回り、統計的有意水準には達していない。

### ⑦ 公休数への副作用

- **公休数違反: Before/After とも 0.000（変化なし）**
- 優先②条件緩和により休み→勤務に転用されたスタッフの公休不足は、既存の「公休数回復フェーズ」（無変更維持）が日勤→休み変換で補正するため、最終的な公休数違反は増加しなかった。

### ⑪ 実装を採用すべきか（実測値のみで判断）

**条件付き採用（さらなる検証が必要）**。

理由（実測値のみ）:

1. **副作用ゼロ**: 公休数違反・連勤違反いずれも有意な悪化なし（連勤違反 t=-0.93/-1.43 で有意水準未達）。生成時間はむしろ改善（★★ p<0.01、shortageが早期に解消されbestOfN内訳が速く収束するため）。
2. **shortage改善の方向性は一貫してプラス**（kaigo1: -0.013, kaigo2: -0.020）だが、統計的有意水準（t>1.96）には未達。
3. **本シミュレーションの fidelity 限界**: Before baseline が Step6-B 実測（17.9/trial）の約 0.1% 水準しかなく、本番相当の制約密度（PassC・比率PassB・ロック日複雑性）を再現できていない。そのため「実際の17.9/trialがどれだけ減るか」は本検証だけでは判定できない。
4. **判定条件の文言「shortageが統計的に改善」は、厳密な統計的有意性（p<0.05）では未達成**。ただし方向性・副作用ゼロという点では前進。
